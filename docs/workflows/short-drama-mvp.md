# 短剧一键生成工作流（MVP）

- 类型：工作流
- 分类：短剧 / AI 视频 / 项目编排
- 状态：review（前半段与审核门有代码/测试证据；完整成片交付待真实验证）
- 难度：进阶
- 分发：公开入门 / 团队标准 / 私域高级交付
- 版本：0.1.0
- 更新时间：2026-08-21
- 维护人：念念团队
- 来源：内部项目 `E:/codex/niannianai/niannianai`

## 一句话结论

念念 AI 的短剧生产不是“输入一句话立即得到完整成片”，而是将故事或已授权原片拆成可审查、可授权、可恢复的生产阶段：先完成剧本事实与镜头设计，再经用户确认进入候选图和视频生成，最后才进入剪辑交付。

## 先选模式

两种路径不能混为同一条“已全自动闭环”的流程。

| 模式 | 输入 | 当前可确认的结果 | 关键边界 |
|---|---|---|---|
| 原创制剧 | 故事梗概、剧本正文或 `.docx` | 源文本登记、事实账本任务、分集/镜头/提示词审核包、候选图与视频授权门 | 完整真实视频生成与最终成片交付仍待验证 |
| 源片转绘 | 有权使用的原片 | 原片预检、语义/时间线规划、角色场景资产、Image2/视频候选任务与外部剪辑入口 | 上传到交付的完整真实闭环仍有执行门禁 |

## 解决什么问题

- 将小说、剧本或原片转成可执行的短剧生产项目，而不是在聊天里丢失角色、世界观和分镜关系。
- 让编剧、分镜、角色资产、图片、视频、剪辑在同一项目状态机中可审查、可恢复。
- 在付费图片/视频生成前设置视觉审核、参考确认、额度/成本和显式提交授权，避免重复扣费与错误生成。

## 适合谁

- **公开用户**：需要理解从故事到短剧的完整生产逻辑、所需输入和审核门。
- **团队成员**：需要执行项目创建、N00–N06 状态推进、候选审核、生成验收和故障回读。
- **私域高级用户**：已具备素材权利与预算，愿意在受控交付中使用模板、提示词包、候选图审查和人工协同。

不适合把未授权小说、剧本、原片或他人角色素材直接投入生成的人群。

## 输入 → 处理 → 输出

```text
原创制剧输入
  项目名 + 题材 + 受众 + 60/90 秒 + 9:16/16:9
  + .docx 或至少 120 字符正文 + 权利确认

处理
  N00 源文本登记与校验
  → N01 故事事实账本
  → N02 分集改编地图
  → N03 镜头事实卡
  → N04 分镜提示词审核包
  → 用户视觉审核与明确授权
  → N05 Image2 候选图
  → 参考确认、成本/规格/提交授权
  → N06 视频生成与成片交付

输出
  可追溯的文本证据、分集/镜头/提示词包、候选图、视频资产、剪辑交付
```

> 当前已证明 N00、N01 任务准备、N04 审核包、N05/N06 授权门与候选任务合同；不能把上图最后的“视频生成与成片交付”描述为已完成的无人值守闭环。

## 原创制剧 SOP

### 1. 录入并确认权利

创建项目时填写项目名称、题材、受众、单集时长和画幅；提交 `.docx` 或至少 120 字符的故事/剧本正文，并明确确认拥有使用与改编权限。

- Word 仅接受 `.docx`，单文件最大 25MB。
- 文本会进行长度校验；项目创建不是视频生成提交。
- 源文本与抽取结果应被登记为项目证据，不应在公开卡片中暴露原文、路径或哈希。

### 2. 完成 N00 源文本登记

系统保存源文本/Word 抽取结果、段落索引和完整性记录，并使项目进入 N01，而不是直接调用图片或视频 Provider。

验收：项目状态显示源文本已核验，视频 Provider 仍处于阻塞或未授权状态。

### 3. 准备 N01 编剧任务

生成 AI 编剧任务包，以故事事实为中心建立人物、关系、世界观和时间线账本。

N01 的要求：

- 基于源文本和段落引用工作。
- 不修改源文本事实。
- 不直接生成图片或视频。
- 产出可回读的任务状态、检查点、产物账本和提示词/任务说明。

### 4. 推进 N02–N04 并做视觉审核

```text
N02：分集改编地图
N03：镜头事实卡
N04：每集提示词审核包
```

N04 就绪后，先让人审核角色、场景、叙事与画面方向。未获得用户视觉接受和显式授权时，不得进入实际图片或视频 Provider 提交。

### 5. N05 候选图与参考确认

在明确授权后生成角色、常驻场景、关键道具或真实首帧等候选图。候选图必须等待确认；拒绝或重做必须记录原因。

此授权只允许受控的候选图流程，不自动等同于视频生成、批量发送、资产注册或公开发布授权。

### 6. N06 视频生成与交付（待真实闭环验证）

在规格锁定、参考图确认、额度/成本核验和明确提交授权后，才允许创建视频任务。实际验收必须证明：

1. 同一提交没有重复扣费或重复提交。
2. 可查询任务状态。
3. 成功结果进入项目资产库。
4. 网站刷新后仍能预览/播放。
5. 最终成片可被用户交付页读取。

在上述真实证据补齐前，N06 只能标记为“待验证”，不能对外承诺一键成片。

## 画布编排参考链

画布中存在另一条用于原创故事编排的链路：

```text
screenwriter
→ chaoge-assets-trial
→ shotlist-builder
→ hell-grind
→ Image2 候选任务
→ H3 / 豆包 / 其他视频渠道候选任务
```

当前该链路的已验证范围是：节点注册、端口连线、输入就绪校验、项目持久化、编排输出和候选任务准备。编排测试不等于真实图片/视频 Provider 已完成生成。

## 源片转绘模式

```text
有权原片
→ 原片预检
→ Step01 语义分析
→ Step02 时间线确认
→ 地区/叙事改编
→ 角色与场景资产
→ Image2
→ H3 / Animate 视频
→ 智能剪辑
→ 成片交付
```

这条路径适用于“已有原片、希望转绘/重构”的需求。当前应按权威执行计划逐段验收，不能把节点 UI、合同测试、Provider 任务号或 HTTP 200 当作最终视频交付。

## 当前已验证能力

- 文本和 `.docx` 输入，含权利确认、文本长度和 Word 大小校验。
- 源文本抽取、章节/段落索引、项目持久化和完整性记录。
- 项目创建后进入 N01，且图像/视频 Provider 默认不提交。
- N01 任务目录、状态、检查点、产物账本与任务说明准备。
- N04 审核包状态回读。
- N05 显式授权、候选图确认/拒绝合同。
- 编剧、资产、镜头表、连续性等画布节点的端口校验、持久化与编排输出。
- dry-run、幂等、项目隔离和敏感字段拒绝。

## 当前不承诺

- 文字或 Word 上传后自动完成完整短剧视频。
- 已完成真实的 Image2 或视频 Provider 生产提交。
- 已完成从脚本到最终 MP4 的无人值守闭环。
- 已完成网站内最终成片的播放、刷新恢复和下载交付。
- 编排测试或 Provider 任务号等同于最终结果。

## 一键应用

### 公开层

- 查看两种生产模式、输入清单和审核节点。
- 领取故事梗概、人物卡、分镜表等脱敏模板。
- 了解“先审核、后付费生成”的生产方法。

### 团队层

- 创建脚本项目与 N00–N06 任务。
- 使用项目状态、产物账本、候选审核与恢复动作。
- 运行真实环境验收：N01 回读、N05 图像生成、N06 视频生成、资产回库、播放和交付。

### 私域层

- 受控交付项目模板、Prompt 包、角色/分镜审核模板、部署协助和生产陪跑。
- 每一次真实图片/视频提交仍必须由拥有素材权利和成本授权的用户确认。

## 验收标准

### 当前可验收的前半段

1. 文本或 `.docx` 录入后，项目创建成功且输入被核验。
2. 项目进入 N01，视频 Provider 未被自动提交。
3. N01 任务包可回读，包含状态、检查点、产物账本和任务说明。
4. N04 可显示为审核就绪，而不是已生成视频。
5. N05 未授权时明确阻塞；候选审核有确认/拒绝原因记录。

### 仍需补齐的全链路验收

1. 真实 N01 产出事实账本并确认段落引用正确。
2. 真实 N02/N03/N04 产物与项目状态一致。
3. 真实 N05 图片生成后回库并可在刷新后查看。
4. 真实 N06 视频提交仅发生一次，能查询、回库、播放与恢复。
5. 最终成片可通过产品界面交付给用户。

## 常见失败与边界

| 情况 | 原因或风险 | 正确处理 |
|---|---|---|
| 文本不足或 Word 无法抽取 | 输入不满足项目创建条件 | 补充正文或更换合格 `.docx`，不要用虚构文本绕过。 |
| 项目创建后没有视频 | 正常：当前首先进入 N01，不会自动提交 Provider | 查看项目状态和任务包，继续完成事实/分镜审核。 |
| N05 被阻塞 | 没有视觉接受或明确图片授权 | 先审 N04，再给出范围明确的授权。 |
| N06 被阻塞 | 规格、参考、额度或提交授权未完成 | 补齐门禁后再创建唯一提交。 |
| 页面有节点但无结果 | UI/合同不等于实际交付 | 检查真实 Provider 查询、资产回库、播放和刷新恢复。 |
| 同任务重复提交 | 网络或状态不确定 | 保留幂等键，先查询既有任务，进入 `review/uncertain`，不盲目重发。 |

## 安全与合规边界

- 仅处理拥有使用、改编、生成和分发权利的文本、原片、角色与素材。
- 不在公开卡、GitHub、Skill 或日志中存放用户剧本、原片、项目 ID、内部路径、哈希、任务 ID、Provider 原始响应、密钥、Cookie、token 或签名 URL。
- 生成费用必须在真实提交前由具备权限的人确认；dry-run 不得被包装为真实生成。
- 将“审核中、等待授权、生成中、失败、已交付”明确展示给用户，避免把剧本摄取或候选任务误导为最终视频。
