- 类型：自动化
- 分类：AI 视频 / 浏览器自动化 / 服务封装
- 状态：已验证（核心端到端链路）；部署方式仍按环境复核
- 难度：高级
- 分发：团队 / 私域

## 一句话结论

把已获授权的豆包工作室视频生成操作封装成 FastAPI 服务：提交分镜提示词后，后台通过 CDP / Playwright 驱动本地工作室完成生成，并把下载到本地的 MP4 以任务状态和结果接口交付给上游系统。

## 解决什么问题

- 上游画布或内部工具无法直接调用浏览器端视频生成流程。
- 人工在工作室中重复完成账号激活、模型/比例/时长设置、提示词提交和结果下载，难以批量化和稳定回收。
- 生成结束后需要让上游拿到可轮询的任务状态和 MP4 结果，而不是依赖人工找文件。

## 适合谁

- **团队成员**：已配置本地豆包工作室、拥有合法授权账号、需要将视频生成接入内部画布或任务系统的开发/运维人员。
- **私域高级用户**：在受控环境中需要参考实现、部署指导或一对一交付的用户。
- **不适合公开用户**：此服务依赖本地桌面工作室、已登录会话与受控浏览器环境，不能作为无账号、无授权的一键 SaaS 承诺。

## 输入 → 处理 → 输出

```text
输入
  分镜提示词 + 模型 + 时长（4–15 秒）+ 画面比例 + 提交模式

处理
  FastAPI 创建任务
  → 自动尝试激活空闲账号
  → 写入 worker manifest
  → Node CDP Worker 向豆包工作室添加任务
  → 工作室内的浏览器自动化分两次发送前置指令和分镜提示词
  → 监控下载目录中的新 MP4

输出
  task_id + running/succeeded/failed 状态 + 本地 MP4 文件流
```

当前实际网关接口见 `app/main.py`：

| 接口 | 作用 | 关键返回 |
|---|---|---|
| `GET /api/v1/capabilities` | 检查网关可用能力并尝试激活账号 | `ready`、模型、比例、时长、提交模式 |
| `POST /api/v1/submit` | 创建视频生成任务 | `task_id`、`status`、账号激活结果 |
| `GET /api/v1/status?task_id=` | 查询任务状态 | `running / succeeded / failed`、错误、结果摘要 |
| `GET /api/v1/result?task_id=` | 在任务成功后返回 MP4 文件 | `video/mp4` 文件流 |

> 历史设计文档中曾使用 `/download` 作为结果接口；当前实现以 `/result` 为准。接入方必须以运行版本的 `/capabilities` 与源码接口为准，不可混用历史接口名。

## 前置条件

1. 已安装并启动受控的豆包工作室，CDP 地址默认是本地 `127.0.0.1:9229`。
2. 本地工作室存在可用、已授权的账号，且自动化有权使用该账号。
3. Worker 文件和 Node 运行时可用；实际路径由部署环境配置，不能将个人绝对路径复制到公开内容。
4. 下载目录可写，且运行账户对目录具有读取权限。
5. 仅提交拥有生成和使用权的提示词、图片、视频、音频与角色素材。
6. 使用方接受平台条款、额度、模型可用性和页面改版带来的不稳定性。

## 使用步骤 / 团队 SOP

### 1. 启动依赖

- 打开受控豆包工作室，确认至少一个授权账号可用。
- 确认 CDP 地址可访问，工作室主窗口和豆包 WebView 未被其他异常实例占用。
- 启动 FastAPI 网关；先调用 `/api/v1/capabilities` 确认网关返回 `ready: true`，并查看账号激活结果。

### 2. 创建任务

向 `POST /api/v1/submit` 发送 JSON：

```json
{
  "prompt": "填写已获授权的分镜提示词",
  "model": "seedance-2.0-fast",
  "duration": 15,
  "aspect_ratio": "9:16",
  "directMode": "ui",
  "poll_seconds": 900
}
```

字段说明：

- `prompt`：必填，不能为空；比例与时长可由网关配置附带。
- `model`：当前默认 `seedance-2.0-fast`；实际支持项以 `capabilities.models` 为准。
- `duration`：4–15 秒。
- `aspect_ratio`：当前能力包括 `1:1`、`3:4`、`4:3`、`9:16`、`16:9`、`21:9`。
- `directMode`：`ui` 表示走工作室视频配置；`direct` 表示按提示词提交，仍需根据实际工作室版本验证。
- `poll_seconds`：Worker 最大等待秒数；不等同于平台生成承诺。

### 3. 轮询和交付

- 使用返回的 `task_id` 调用 `/api/v1/status?task_id=`。
- `running`：继续轮询；不要重复创建同一任务。
- `failed`：记录 `error` 和时间，先检查账号、CDP、工作室状态、模型和下载目录，再决定是否重试。
- `succeeded`：调用 `/api/v1/result?task_id=` 获取 MP4 文件流，并把文件注册到上游资产系统。

- 服务实现将长时间 Worker 放入 `asyncio.to_thread`，以避免 Worker 执行期间阻塞 `/status` 和 `/result`；见 `app/main.py` 的 `_run_worker`。

验收时必须重新执行以下最小检查：

1. `/capabilities` 返回 `ready: true`，并记录账号激活结果。
2. 提交一条低成本、已授权测试提示词，得到 `task_id`。
3. 在合理等待期内轮询到 `succeeded` 或清晰的 `failed` 错误。
4. 成功时 `/result` 返回可播放、非空的 `video/mp4`。
5. 失败时保留错误和环境信息，但不把 Cookie、账号、完整下载 URL 写入日志或知识库。

## 常见失败与边界

| 现象 | 先检查 | 处理原则 |
|---|---|---|
| `prompt 不能为空` | 请求体 | 传入非空、已授权的分镜提示词。 |
| `任务不存在` | `task_id`、进程重启 | 网关任务状态当前在内存中；服务重启后历史任务不可查询，需避免把它当持久队列。 |
| 账号激活失败 | 工作室窗口、空闲账号、CDP | 不要盲目重试；先确认工作室和账号状态。 |
| 长时间 `running` | Worker、平台生成状态、下载目录 | 等待至 `poll_seconds`；检查 Worker 输出和下载目录，不依赖单一 UI 文案。 |
| `result` 返回 409 | 状态尚未成功 | 继续查 status，不要提前下载。 |
| `result` 返回 404 | 下载目录或 Worker 结果 | 确认实际下载文件、读写权限和 Worker 输出。 |
| 平台页面改版导致自动化失败 | 选择器、工作室版本 | 将问题标记为待验证，更新 Worker 或控制器后重新做真实测试。 |

## 安全、合规与运维边界

- 仅使用已获授权的账号、平台功能和素材；不得将自动化用于绕过账号、权限、额度或平台限制。
- 不提交、不记录、不分享 Cookie、账号 profile、密钥、签名 URL、个人下载目录或用户素材。
- 当前任务状态保存在进程内存中，服务重启会失去任务查询能力；生产化前需要外置持久化队列和结果存储。
- `app/main.py` 依赖特定本地 Worker、CDP 和下载目录；迁移环境必须参数化路径并重新验收。
- 旧的 Playwright 控制器和 README 仍保留设计参考，不等于当前网关默认执行路径；以实际 Worker 链路和版本化测试结果为准。
